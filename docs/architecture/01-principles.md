# 01 · Principles

Status: Draft · Version 0.1

These are the rules the code already follows. Each one names what enforces it; a rule with nothing enforcing it is not on this list. A change that breaks one needs an ADR first.

| P1  | **One service layer, many transports.**                                               | REST routes, MCP tools and the worker all call the functions in `packages/server/src/services` with an `Actor`. No `services/*.ts` file imports a route, an MCP module or Hono. A feature that exists in only one transport is a bug in the making.                                                                                                                                                                                                                                        | A grep, not a lint rule or test: no `services/*.ts` file imports `routes/`, `mcp/` or `hono` directly, though they import `ApiError` from `src/http.ts`, which itself imports `hono`; `mcp/coverage.test.ts` classifies every route in the top-level `routes/*.ts` files as an MCP tool or a stated reason. | 0002 |
| P2  | **Authorization lives in one function, and "no access" is a 404.**                    | `getRadarAccess` and `requireRadar` in `services/access.ts` are the door to a radar (with `requireHelpdeskRadar` and `readableRadarIds` in the same file for the helpdesk and list cases). A radar the caller may not read is a 404, never a 403, because a 403 confirms the id exists.                                                                                                                                                                                                    | `services/access.ts`; the 404 is asserted in `services/agent-boundary.test.ts` and `public-link.test.ts`; `services/topic-visibility.test.ts` and `services/co-owners.test.ts` cover topic-name hiding and role refusals.                                                                                   | 0003 |

## Precedence when principles collide

Account and data safety (P2, P4, P6) outrank convenience; fail-closed behaviour (P15) outranks availability; the database's verdict (P7) outranks any application check that disagrees with it. For example, a notification that cannot be attributed to a live reader is dropped, not delivered.

## What is not a principle here

- **"CI has no cluster access."** It is the company standard, but OMR's release pipeline does call `kubectl` under the runner's service account (`scripts/prepare-release.sh`, `scripts/deploy-release.sh`). This is recorded as a known gap in `components/release-deploy.md`, not claimed as a rule.
- **"`unfurl.ts` is the only outbound fetch to a user URL."** Older briefs say so. The code has five callers of `publicRequest` (P10) and several fixed-host callers that use plain `fetch`.
